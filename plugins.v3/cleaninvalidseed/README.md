# 清理无效做种 3.0

适用 MoviePilot 3.1.6 及以上的 V3；支持 qBittorrent 和 Transmission。V1/V2 实现不在本次迁移范围内。

## 检测与清理

在插件卡片打开「做种复核」。页面的「只读检测」只读取任务与目录，不执行定时处理方式，也不发送通知。

| 状态 | 含义 |
| --- | --- |
| 待复核 | 所有有效 Tracker 都明确返回删种错误，同一 Tracker 还有其他任务成功做种；进入持续观察 |
| 可处理 | 观察次数与观察时长均已满足；还需通过执行前复核 |
| 需检查 | 网络、账号、权限、站点故障，或缺少同站点成功做种的佐证；保留任务 |
| 已保护 | 命中排除条件、暂停、下载未完成、校验、排队、本地数据异常或累计做种不足 |
| 信息不足 | 无法取得有效 Tracker 信息；保留任务 |

默认至少观察两次、持续 24 小时、累计做种至少 10 天，每批最多处理 10 项。有效观察之间至少相隔一小时；下载器读取失败会中断连续观察。过长的检测中断也会重新开始观察。

匹配使用完整错误文本，忽略大小写、连续空白和结尾标点。自定义规则中的网络、账号及权限错误会被忽略。qBittorrent 正在更新的 Tracker 不算成功佐证；Transmission 必须确实有过 announce。

可手动追加标签，或移除任务并保留文件。移除后需重新添加种子才能恢复做种。每次操作前重新获取当前状态，操作后回读下载器；接口响应成功但任务仍在时，记录为「需核对」。检测计划十分钟过期，变更配置后失效。

## 源文件与回收区

勾选源文件检测后，会核对**全部已配置下载器**，包括判断停用的下载器是否存在未能核对的任务。任一下载器不可用、停用、类型不支持或内容路径未知，都不会执行源文件处理。仅选择 TR 检测失效种子，不会忽略 QB 对源文件的引用。

每行映射格式：`MP目录:下载器目录1,下载器目录2`。要求具体的绝对目录；MP 目录之间、不同映射行的下载器目录之间不能重叠。没有任何在用任务对应的映射无法验证，不会据此判定整个目录为空闲。

路径按目录边界比较，双向保护祖先和后代。Transmission 使用实际文件清单，因此改名后的内容不会按原种子名称误判。只检查映射目录的直接子项；包含软链接、特殊文件、跨设备内容、挂载点或未完成下载文件的项目跳过。文件和目录内任一后代近期变化，也会重新等待。

源文件定时任务只检测。满足观察条件后，可在页面选中源文件、输入确认文字，移入该源目录内的 `.cleaninvalidseed-trash`。它与源文件位于同一文件系统，保留字节、硬链接及恢复记录；**继续占用磁盘空间，插件不会永久删除**。回收区页面可恢复到原位；原位置有同名内容时保留双方，不覆盖。

移动前先持久化意图和原位置；移动和恢复均使用操作系统的无覆盖重命名，即使目标在检查后被其他程序创建，也不会覆盖。系统不支持该操作时保留源文件并报告失败。发生中断时，回收区中的内容及恢复记录保留。回收区活动条目不会随普通日志过期。最多保留 1000 个活动回收区条目，达到上限后停止移动。

外部下载器不提供与文件系统共同的事务锁，因此重新添加任务和移动源文件之间仍有很短的竞争窗口。持续观察、逐项重新获取清单、文件指纹校验及可恢复移动共同降低影响；如需绝对禁止影响其他任务，请只使用种子任务预览/标记。

## 升级与运行

旧版周期、下载器、目录映射和排除规则沿用，旧版删除开关不会自动迁移为自动删除。默认转为「只预览」。旧版“最小做种天数”还会迁移为源文件静置天数；新版任务保护使用下载器真实累计做种时长。

定时处理方式提供只预览、追加标签、移除任务并保留文件。源文件移动始终需要在工作台确认。旧版通过聊天直接删除源文件的命令不再注册，使用经过确认的工作台或认证 API。

页面提供搜索、状态与类型筛选、分页、选中项确认、操作历史和恢复入口。支持窄屏、宿主深浅色主题及键盘焦点。页面每三秒检查变化；没有变化时只返回版本标记及运行状态，避免重复传输数千条任务。

配置和状态沿用 MP 插件数据存储。单进程锁和文件锁防止定时、手动、重载及多进程重复执行；停止或重新保存配置会取消旧的检测。历史最多保留 200 条，单项意图在确认后更新为最终结果。

## API

以下接口均经过 MP 认证；`/page_*` 为同功能的登录用户接口。

- `GET /api/v1/plugin/CleanInvalidSeed/status`：状态、证据、记录与回收区；可传 `revision` 获取轻量变化响应。
- `POST /api/v1/plugin/CleanInvalidSeed/scan`：启动只读检测，异步完成。
- `POST /api/v1/plugin/CleanInvalidSeed/execute`：请求体 `scan_id`、`ids`、`action`、`confirmation`；操作值及确认文字分别为 `tag` / `标记选中任务`、`remove` / `移除任务并保留文件`、`quarantine` / `移入回收区`。
- `POST /api/v1/plugin/CleanInvalidSeed/restore`：请求体 `id`，恢复回收区条目。

Tracker URL、passkey 和未脱敏的响应不会发送到工作台。GET 接口不执行清理操作。
